# Acceptance status

Working offline implementation with development qualification; **comprehensive A1–A12 completion remains open**. This matrix applies the existing [acceptance criteria](../ACCEPTANCE.md), without lowering their evidence requirements. “Engineering verified” means the stated implemented behavior passed the referenced checks; it does not establish representative accuracy or operational certification.

## Verified evidence snapshot

- Final full regression run: **151 passed** in 108.23 seconds; source tests in [tests](../tests/). These are authored engineering cases. Native Windows process handles independently confirmed that page/open timeouts kill the actual interpreter and release PDF locks; testing exposed and corrected an earlier launcher-only termination defect.
- Authentic corpus: **five admitted manuals, 616 pages; 610 successfully processed, six damaged pages explicitly failed**. Four powered-equipment manuals plus one hand-tool negative control; two additional rights candidates excluded. Execution success does not certify OCR correctness.
- Raw layout extraction: **21 candidates**. Selected field matches **13/17**, versus line baseline **4/17**. References are selected agent-inspected development leads; conditions are not fully scored, so these ratios are neither exhaustive recall nor full-assertion precision. [Extraction results](extraction-development.json), [interpretation](extraction-development.md).
- Exhaustive original M18 candidate audit: **5/17 fully scoped**, nine missing scope and three wrong entities; two supported observations duplicate other claims. After repairs: **7/7 supported** on the same inspected source. Original errors retained; repaired-data success provides no untouched/generalization result. [Original audit](../data/corpus/m18-candidate-audit-v1.json), [repair audit](../data/corpus/m18-candidate-audit-v2.json).
- Actual agent-reviewed development catalogs: five documents, **14 reviewed/corrected observations, seven pending candidates**. Values-profile recall@10 **0.9118**, MRR@10 **0.9412**, identically for lexical and ontology TF-IDF rankers; 17 known-positive queries / 22 labeled scopes within 33 source-reference cases. Coverage-profile recall@10 **0.9286** across seven known-positive queries / 12 scopes. Three synthetic queries reported separately. No measured relevance advantage justifies replacing default BM25. [Retrieval results](retrieval-development.json), [denominators and failures](retrieval-development.md).
- Final wheelhouse: discovery and extraction fresh-environment qualification both **passed**, installed from pinned local wheels with no index/cache; guarded runtime reported zero Python network attempts. Extraction also verified the actual native worker PID. Discovery had no private source files or OCR packages. These proofs cover the existing Windows host, not a clean target or OS-enforced air gap. [Discovery proof](../wheelhouse/vopt-0.1.0-qualified/proof-discovery.json), [extraction proof](../wheelhouse/vopt-0.1.0-qualified/proof-extraction.json), [artifact manifest](../wheelhouse/vopt-0.1.0-qualified/manifest.json). Portable-runtime qualification is recorded separately in [build verification](build-verification.json).
- Both portable runtimes **passed** using their bundled, relocated CPython interpreter; no external Python or installer required. Runtime source archives exclude real research data. Actual five-document / 14-observation discovery also passed without OCR dependencies or original PDFs in its input directory. [Catalog-only proof](catalog-only-runtime-proof.json). The frozen 616-page evaluation predates worker hardening; records retain their original processing signatures instead of silently rewriting provenance.

## Completion gates

1. Declare supported scope and obtain representative, rights-qualified families covering difficult scan/layout/model combinations; keep related editions together.
2. Obtain independent human full-assertion/relevance labels with adjudication and effort measurements. Freeze untouched families/queries, numerical gates and configuration before final testing; preserve first failures.
3. Extend resource qualification beyond implemented native deadlines: hard memory limits, parent-death cleanup and bounded interactive review rasterization; test on representative hostile/damaged PDFs.
4. Run the qualified portable runtime and entire frozen workflow on actual target hardware/OS with networking unavailable. Existing Python guards and same-host relocation cannot substitute for this test.
5. Resolve project and dependency/model redistribution obligations separately from corpus rights; package qualified assets and write the PDF chapter with explicit evidence limits.

No human-gold accuracy, untouched generalization, labor savings, multilingual competence or classified-system validation is claimed by this checkpoint.
