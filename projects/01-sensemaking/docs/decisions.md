# Agreed direction

The design interview is complete. The user agreed to all five final proposals
and delegated implementation, evaluation, documentation, and packaging, with
concise milestone walkthroughs and consultation on consequential changes.

## Product and evidence

- A comprehensive portfolio of working solutions, explanations, inspectable
  evidence, and accessible demonstrations. SCADS provides the project framework.
- Synthetic data first; then public research-organization cases using ROR and
  Wikidata. Sources must be qualified before making factual or licensing claims.
- Questions concern organizational structure, relationships, changes, and
  conflicting evidence. Agreement between databases sharing an upstream source
  does not establish independent corroboration.
- The finished local workflow must run without paid subscriptions or model APIs.
  Existing Codex access is allowed for development and an optional agent path.
- Scaling means removing a fixed dataset ceiling, measuring practical limits,
  and documenting compute/storage tradeoffs. It does not mean infinite resources.
- Website visitors explore completed interactive cases and can reproduce them
  locally. Arbitrary public model inference is not required.
- PDFs follow completion and polish of the solutions.

## Evidence required before completion

The agent must actually choose tools, consume evidence, and synthesize an
inspectable report. A scripted packet or a plausible-looking page is insufficient.
Report factual support, completeness, conflicts, ambiguity, repeatability, costs
in time/resources, and errors against declared tasks and baselines. Fix evaluation
cases before tuning on their results. Label automated comparisons honestly;
human analyst-time savings require human measurement.

The Project 4 export adapter now passes actual MCP source-reading and typed
reporting-line traversal checks. Its real backup contains a one-hop relationship;
the two-hop conformance fixture is separately authored. Sibling model-analysis
acceptance remains open. Preserve shared interfaces and claim only boundaries
actually exercised end to end.

## Evidence overview construction

Two local trials preserved supporting findings and conflicts but overstated
unresolved readiness in their opening summaries. The implementation now offers an
optional host-authored evidence overview built from actually retrieved source
assertions, dates and identifiers. Competing values remain unresolved candidates;
later dates and repeated records do not determine truth.

This is a disclosed construction policy, not a semantic verifier. The model still
chooses tools and authors findings, explanations and conflict descriptions.
Independent source review still checks those fields. Previous model outputs remain
unchanged. The overview must work on compatible external datasets without fixture
names, hidden answers, unseen records or source-text instructions.

The implemented overview passed reconstruction checks, but trial12's model-authored
finding still overstated readiness. The larger 9B model retained source attribution
in trial13 but added an unsupported exclusive cause. Both remain rejected.

Generic v12 report guidance asks for complete, source-supported relationship paths,
dated qualifications, and planned/actual distinctions. It supplies no fixture
answers and changes no acceptance rule. Trial14 passes the unchanged review for
one known synthetic case; original wording and minor disclosed caveats remain.
This development history demonstrates repair and scrutiny, not general reliability.
